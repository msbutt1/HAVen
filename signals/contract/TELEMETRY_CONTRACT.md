# VibeGuard device telemetry contract — v1 (PROPOSED)

**Status: proposed, pending review by Abduljabbar (ingestion) and Ali (display).**
Owner: Salaar. Authoritative validator: `signals/src/vibeguard_signals/contract.py`
(`uv run vg-validate …`). If this document and the validator disagree, the validator
is the reference and the disagreement is a bug to report.

## Scope

Covers **device → host** telemetry from the wearable (real firmware or the simulator):
what the acquisition side emits before any processing.

It does **not** cover:
- the backend/frontend API, session or calibration endpoints, storage, or live delivery
  (Abduljabbar);
- station test sequencing, trials, or responses (Fahad);
- host → device commands. Controller-level stimulus commands will be a separate contract
  agreed with Fahad.

## Processing boundary

The device only acquires samples: it timestamps raw samples, sequences them, and flags
quality. All filtering, envelopes, calibration, vibration features, and the experimental
score run on the host, in the `vibeguard_signals` reference package. Nothing is processed
on the device until a measured reason (link bandwidth, latency) justifies porting a
specific stage.

## Framing

- **Simulator/host transport:** newline-delimited JSON (NDJSON), UTF-8, one record per
  line. A frame is at most **65,536 bytes including the newline**. `\r\n` is tolerated.
  Blank lines are invalid frames.
- Strict JSON: `NaN`, `Infinity`, numbers that overflow to infinity, and duplicate keys
  are rejected.
- **Physical wire format is not decided.** At provisional rates, verbose JSON does not fit
  a 115200-baud UART (see *Bandwidth*). The eventual wire format (for example, a compact
  binary frame with COBS + CRC) must decode to exactly these logical records, so
  consumers do not change.

## Common fields (every record)

| Field | Type | Meaning |
|---|---|---|
| `schema` | `"vibeguard.device_telemetry"` | Contract identifier. |
| `version` | integer `1` | Contract major version. Other values → `unsupported_version`; reject and do not guess. |
| `type` | `hello` \| `status` \| `emg_batch` \| `imu_batch` | Record kind. |
| `device_id` | id string | Stable per physical device or simulator instance. |
| `boot_id` | id string | New random value on every boot / stream start (power cycle, reset, simulator restart). |
| `seq` | integer ≥ 0 | Record sequence number; see *Sequence scope*. |
| `provenance` | object | `live`, `simulated`, or `replay`; see *Provenance*. |
| `ext` | object, optional | Experimental extras. Consumers must ignore it. |

Id strings: 1–64 characters of `[A-Za-z0-9._:-]`. Any other top-level field is rejected
(`unknown_field`), so typos fail loudly.

### Sequence scope and reboot/reset

- `seq` is a **single counter per (`device_id`, `boot_id`)**, shared by all record types.
  It starts at 0 (the `hello`) and increments by exactly 1 for each record emitted.
- A jump forward (`seq` > last + 1) means whole records were lost: `seq - last - 1` of them.
- A `seq` ≤ the last one seen for the same boot is a duplicate or out-of-order record. The
  consumer drops it and counts it.
- A **new `boot_id`** means reset. `seq`, `first_sample_index`, and device time all restart.
  Never join timelines, sample indices, or integrations across boot IDs. A boot change
  invalidates downstream windows and calibration state until the host decides otherwise.

### Provenance

| `source` | Meaning | Extra fields |
|---|---|---|
| `live` | Emitted now by real firmware from real sensors. | — |
| `simulated` | Generated by software. **Never present as live.** | optional `recording_id`, optional `detail` (e.g. seed, scenario) |
| `replay` | Re-emission of an earlier recording. | **required** `recording_id`, **required** `original_source` (`live` \| `simulated`) |

Replay must preserve the original `device_id`, `boot_id`, `seq`, and device timestamps.
Only `provenance` changes. Any accelerated playback rate is declared by the replay tool
outside these records; it never alters `t0_us`/`t_us`. The simulator must never emit
`source: "live"`.

## Time

- Timebase: **device-monotonic microseconds since boot**, as an integer. It is not wall
  time. Values ≤ 2^53−1. Firmware must extend a wrapping 32-bit `micros()` (which wraps
  after about 71.6 min) to 64 bits before emitting.
- Device time is meaningful only within one `boot_id`. Wall-clock receive time is added by
  the host ingestion side (Abduljabbar), not by the device.
- The real sample rate and jitter are **measured from these timestamps** on hardware. They
  are not assumed from `sample_rate_hz`.

## `hello`

Sent first after boot (`seq` 0), and may be re-sent at any point (e.g. on host reconnect).

| Field | Meaning |
|---|---|
| `t_us` | Device time of emission. |
| `firmware` | `{name, version}`. |
| `streams` | Map of `emg` / `imu` → `{nominal_rate_hz, channels, units, conversion?, raw_limits, sensor_model}`. |
| `hardware` | Optional map of up to 16 string-or-null facts (board, front end, bus…). |

`nominal_rate_hz`, `raw_limits` (`{min, max}` integers), and `sensor_model` are **required
keys that may be `null`**, meaning *unresolved*. Today every hardware value is `null`
because no models are confirmed. Clipping can only be detected once `raw_limits` are known.

## `status`

`{t_us, state, sensors, counters?, message?}`. `state` is the **device** state: `booting`,
`ready`, `streaming`, or `error`. Host-level states (disconnected, calibrating, recording)
belong to the backend. `sensors` maps `emg`/`imu` to `ok`, `disconnected`, `stale`, or
`unknown`. `counters` holds non-negative integer totals (for example dropped samples or
overruns since boot).

## `emg_batch` and `imu_batch`

EMG and IMU are **separate streams in separate batches**, each at its own rate. No
one-to-one sample pairing is fabricated; the host aligns streams by device time.

| Field | Meaning |
|---|---|
| `sample_rate_hz` | Nominal configured rate, in (0, 20000]. |
| `first_sample_index` | Per-stream count of samples acquired since boot, at the first row of this batch. It includes dropped samples, so index jumps reveal device-side loss. |
| `timing` | Either `{"mode":"uniform","t0_us":int,"interval_us":number}`, where sample *i* is at `t0_us + i·interval_us`, or `{"mode":"explicit","t_us":[int,…]}` with one strictly increasing timestamp per row. |
| `channels` | EMG: `emg0`…`emg7`. IMU: any of `ax ay az` (accelerometer) and `gx gy gz` (gyroscope). Unique; at most 8. |
| `units` | Map: channel → unit. Keys must equal `channels`. |
| `conversion` | Required for every physical-unit channel, and only for those: `{scale, offset?, source}`, with physical = raw·scale + offset. `source` states where the conversion came from. |
| `samples` | 1–256 rows. Each row is a list with one value per channel, in `channels` order. |
| `quality` | `{flags: [...], dropped_samples_before?: int}`. |

### Units

| Kind | Raw (default) | Physical (only with `conversion`) |
|---|---|---|
| EMG | `adc_counts` (integers) | `mV` |
| Accelerometer | `raw_counts` (integers) | `m/s^2` |
| Gyroscope | `raw_counts` (integers) | `deg/s` |

Raw ADC counts **stay counts** until a conversion is known from the confirmed hardware.
Count values must be integers with |v| ≤ 2^31−1. Physical values are finite numbers.

### Timing consistency

The mean interval (uniform `interval_us`, or the mean step of explicit `t_us`) must be
within **±10 %** of `1e6 / sample_rate_hz`. A wider gap means the metadata contradicts
itself, and the record is rejected as `timing_inconsistent`. Smaller deviations are
legitimate clock error. Firmware should send the **measured** interval, and the host
measures the true rate from timestamps. Explicit timestamps must strictly increase, with
exactly one per row.

## Dropouts, missing values, and staleness — never zeros

| Situation | Representation |
|---|---|
| Whole records lost in transport | Gap in `seq`. |
| Samples lost on the device (buffer overrun) | `first_sample_index` jumps; `quality.dropped_samples_before` = count lost immediately before this batch; flag `overrun`. A non-zero `dropped_samples_before` requires `overrun`. |
| Individual samples unavailable | `null` in that cell plus flag `missing_values`. The flag and the presence of nulls must agree. |
| Sensor disconnected | **Every** value `null`, plus flags `sensor_disconnected` and `missing_values`. A `status` record should report the sensor as `disconnected`. Numeric placeholders (0, −1, last value) are rejected. |
| Sensor not updating (device detects repeated/no-new data) | Flag `stale` on the batch; `status.sensors.<stream> = "stale"`. |
| Host stops receiving a stream | Host-side staleness. The consumer marks the stream stale when no batch arrives within its freshness limit (defined in the host processing step). Old values must not be shown as current. |

Other flags: `clipped` (values at known `raw_limits`), `timing_irregular` (device saw
jitter beyond its own threshold), `warmup` (sensor settling after start).

## Limits

| Limit | Value |
|---|---|
| Frame size | 65,536 bytes including the newline |
| Rows per batch | 256 |
| Channels per batch | 8 |
| Free-text strings | 200 chars |
| Integers (seq, index, time) | 0 … 2^53−1 |

Recommended batch duration is about 50 ms. That keeps latency acceptable and stays far
inside the frame limit: the largest legal batch, 256 rows × 6 channels, measures about
11.7 KB as compact JSON.

## Bandwidth (provisional — rates are assumptions)

Output of `uv run vg-bandwidth`: 50 ms batches, worst-case value widths, real serialized
records.

| Configuration | JSON B/s | UART load @115200 | @921600 | Hypothetical binary B/s |
|---|---|---|---|---|
| EMG 1 ch @500 Hz + accel 3 ax @100 Hz | 21,540 | 187 % | 23 % | 2,680 |
| EMG 1 ch @1000 Hz + accel 3 ax @400 Hz | 31,940 | 277 % | 35 % | 5,480 |
| EMG 1 ch @1000 Hz + accel 3 ax @1000 Hz | 45,760 | 397 % | 50 % | 9,100 |

Conclusion: NDJSON is fine for the simulator and for pipes or files on the host. On a
physical UART it needs ≥ 460800–921600 baud, or native USB CDC, or a binary encoding.
The choice waits for the confirmed board and a measured throughput test.

## Error codes

Each issue carries a stable `code` and a `path`:
`line_too_long`, `not_utf8`, `empty_line`, `malformed_json`, `duplicate_key`,
`nonfinite_value`, `not_object`, `wrong_schema`, `unsupported_version`, `unknown_type`,
`missing_field`, `unknown_field`, `invalid_value`, `limit_exceeded`, `shape_mismatch`,
`timing_inconsistent`, `missing_conversion`, `unexpected_conversion`,
`quality_inconsistent`, `provenance_inconsistent`.
Invalid records are rejected whole. Consumers must not partially use them.

## Fixtures

- `fixtures/valid/*.json`: one pretty-printed record each (hello, status, EMG uniform,
  IMU explicit raw, IMU physical units with simulator conversion, EMG gap + missing values,
  EMG sensor disconnected, EMG replay).
- `fixtures/valid/stream_simulated_boot.ndjson`: one simulated boot in emission order,
  `seq` 0–7.
- `fixtures/invalid/*.json`: one defect each; `fixtures/invalid_manifest.json` lists the
  expected code and reason.

All fixture data is simulated and hand-authored. Values are arbitrary: they imply no ADC
resolution, sensor range, or real signal behaviour.
