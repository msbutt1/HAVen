# HAVen station contract — v1 (PROPOSED)

**Status: proposed, pending review by Ali (screens), Abduljabbar (storage) and Salaar (controller firmware).**
Owner: Fahad. Reference implementation: `station/src/haven_station/`. The validators in
`contract.py` are authoritative; if this document and a validator disagree, that is a bug.
Every payload in `contract/examples/` is generated by the engine and checked by the tests.
All examples are **simulated**.

## Framing (applies to every label and screen)

- The station is a **vibration-perception prototype**. It does not diagnose or detect nerve
  damage. Say "early-warning prototype".
- The stimulus is a **motor setting**: a command to the motor driver. It is not a measured
  physical amplitude. `measured_amplitude` is always `null` (the station has no accelerometer).
- The setting range (default 1–100, 0 = motor off) is an **assumed placeholder** until the
  driver is confirmed. Every result says so (`setting_range_assumed`).
- A **timeout is `missing`**, never `not_felt`.
- A **preview** is a short judging run. It is labelled `PREVIEW_…` and is not equivalent to a
  full test.
- Contact pressure is **not measured or controlled** (`contact_pressure_uncontrolled`).

## Engine states

```
ready --start--> testing --stop rule met--> completed
testing --abort--> aborted
testing --adapter failure / unconfirmed stop--> error
```

`snapshot()["phase"]` refines `testing` into `between_trials` and `awaiting_response`; it is
`idle` in `ready` and `done` in any terminal state.

## Staircase (prototype protocol, not a validated medical procedure)

| Rule | Full | Preview |
|---|---|---|
| Start / step (motor setting) | 60 / 5 | 60 / 10 |
| Felt | next stimulus weaker | same |
| Not felt | next stimulus stronger | same |
| Reversal | change of direction; its level is the setting of the trial whose response flipped it | same |
| Stop | 8 reversals | 4 reversals |
| Threshold | mean of the last 6 reversal levels | mean of the last 2 |
| Catch trials | ~1 in 6, never first two stimulus trials, never back to back | none |
| Max trials | 60 | 20 |

Other endings (no threshold): `floor_reached` (felt at the lowest setting 3 times in a row),
`ceiling_reached` (not felt at the highest 3 times), `max_trials_reached`,
`too_many_missing_responses` (3 missing in a row), `aborted`, `abort_stop_not_confirmed`,
`adapter_error`. A missing response repeats the same level and never moves the staircase.
Catch trials (setting 0) never move the staircase; "felt" on one is a catch-trial failure.

Timing defaults: stimulus 1000 ms, response window 4 s from the stimulus command,
1 s between trials. A response is accepted only for the trial currently waiting and inside
its half-open window [command, command + window); a response exactly at the deadline is late. Late, stale (wrong trial) and unsolicited responses are ignored and counted.

## Records

All records carry `schema` and `version: 1`. Id strings are 1–64 characters of
`[A-Za-z0-9._:-]`. Provenance is `{source: live | simulated | replay}` with the same rules as
the telemetry contract (replay needs `recording_id` and `original_source`). The simulated
adapter and the simulated controller can never produce `live`.

### `vibeguard.station_result` (saved once per session)
Examples: `result_full_simulated`, `result_preview_simulated`, `result_aborted_simulated`,
`result_preview_with_missing_response`.

| Field | Meaning |
|---|---|
| `session_id`, `mode` (`full`\|`preview`), `is_preview` | identity |
| `state` (`completed`\|`aborted`\|`error`), `outcome` | how it ended; see above |
| `result_label` | `vibration_perception_staircase_estimate_prototype` or `PREVIEW_short_run_not_equivalent_to_full_test` |
| `framing` | the standing disclaimer; show it |
| `provenance`, `stimulus_units` (`motor_setting`) | data source and unit label |
| `threshold` | `{value, units, method, reversal_levels_used, reversal_spread}` only when `outcome == threshold_estimated`, else `null` |
| `reversals` | `{count, levels, required}` |
| `trial_counts`, `catch_trials` | totals; catch `{trials, passed, failed, no_response}` |
| `quality.limitations` | list of `{code, message}`; always includes `motor_setting_not_measured_amplitude` and `contact_pressure_uncontrolled`; adds `preview_not_full_test`, `data_simulated`, `missing_responses`, `catch_trial_false_positives`, `no_catch_trials`, `late_responses_ignored`, `duplicate_responses_ignored`, `unsolicited_responses_ignored`, `non_button_response_source`, `unstable_staircase`, and the outcome codes |
| `abort_reason`, `error` | set for aborted / error sessions |
| `config` | the full configuration used |
| `started_at`, `ended_at`, `duration_s` | wall-clock stamps and elapsed engine time |
| `trials` | the trial records below |

### `vibeguard.station_trial`
Example: `trial_example`. `kind` is `stimulus` or `catch`; `stimulus_setting` is the motor
setting (0 for catch); `response` is `felt`/`not_felt` only when `response_status` is
`received`; other statuses are `missing`, `aborted`, `error` and have `response: null`.
Times are seconds since session start; `latency_ms` is response time minus command time.
`staircase` (`direction`, `reversal`, `reversal_level`, `next_setting`) is set for stimulus
trials with a received response.

### `vibeguard.station_event` (live stream for screens)
Examples: `event_state_changed`, `event_trial_started`, `event_trial_completed`,
`event_reversal`. Every event has `session_id`, `seq` (1, 2, 3, …), `t_s`, `state`, `provenance`.
Types: `state_changed`, `trial_started`, `trial_completed`, `reversal`, `response_ignored`,
`session_result` (carries the full result), `result_saved`, `result_already_saved`,
`result_save_failed`.

### Status snapshot
Example: `status_snapshot`. `engine.snapshot()` for a screen to poll: state, phase, mode, current
trial and setting, reversals so far, provenance. It is display-only; the result is the record.

## Using the engine

```python
from haven_station import ResultStore, StationConfig, StationEngine
engine = StationEngine(adapter, StationConfig.preview(), sink=ResultStore("results"))
engine.start()
while engine.state == "testing":
    for event in engine.tick():        # call every ~50 ms; the engine never sleeps
        publish(event)
# UI button handlers call engine.submit_response("felt" | "not_felt", source="on_screen")
# an abort button calls engine.abort()   (stops the motor first)
```

The sink is called once with the result dict; its return value is ignored. `ResultStore` as a
sink raises `AlreadySavedError` when that session id already has a file (never overwritten);
the engine then sets `already_saved` and emits `result_already_saved`. (`ResultStore.save`
is the same operation returning a bool.) A sink that raises leaves `engine.save_error` set and
`engine.retry_save()` tries again. The result is never lost and never saved twice.

## Controller link (PROPOSED; for Salaar; not yet run against hardware)

NDJSON over USB serial, one object per line. Times: the host stamps each event on receipt.

Host → controller, `schema: vibeguard.station_command`:

| `type` | Fields | Meaning |
|---|---|---|
| `hello` | `command_id` | identify yourself; answered with a `hello` below |
| `deliver_stimulus` | `command_id`, `trial_id`, `setting` (int ≥ 0), `duration_ms` | run the motor at that setting for that long; setting 0 = motor off (catch trial) |
| `stop_stimulus` | `command_id` | motor off now |

Controller → host, `schema: vibeguard.station_link`:

| `type` | Fields | Meaning |
|---|---|---|
| `hello` | `command_id?`, `firmware: {name, version}`, `setting_range: {min, max}` | sent on boot and in answer to a `hello` command. `setting_range` is the motor settings the controller accepts (integers, `1 <= min < max`; 0 is always "off"); **the host scales the staircase to it**, replacing the assumed 1–100 placeholder. A hello with no `command_id` after the handshake means the controller rebooted: the host ends the session in `error` |
| `ack` | `command_id`, `status` (`accepted`\|`rejected`\|`completed`), `reason?` | `deliver_stimulus` is `accepted` (or `rejected`); `stop_stimulus` is `completed` once the motor is confirmed off |
| `stimulus_started` / `stimulus_ended` | `trial_id`, `device_t_us` | motor timing |
| `response` | `response` (`felt`\|`not_felt`), `device_t_us`, `trial_id?` | button press |
| `error` | `message` | controller fault; ends the session in `error` |

The host sends `hello` when it connects and resends it every second for up to 5 s (a board that
resets when the port opens misses the first one; its boot-time hello also counts). It refuses to
send a setting outside the reported range. It treats a missing `ack` within 1 s as a fault and a
missing stop confirmation within 0.5 s as `abort_stop_not_confirmed`. The next stimulus is never
sent while the previous one is still running (`busy` is a rejection). A stop is sent whenever a
session ends. Lines that are not valid link messages are counted and ignored.
Defaults: 115200 baud, USB serial, one line per message, lines up to 255 bytes. Ids are 1–64
characters; session ids are limited to 58 so that trial ids (`<session_id>-tNNN`) fit.
A `stop_stimulus` is honoured as soon as the controller recognises it, even if the rest of the
line is damaged; any other command must be a single flat, well-formed object (no junk before or
after, no repeated keys) or it is ignored or rejected. A source is labelled `live` only when the
transport explicitly says it is real hardware; anything else is labelled `simulated`.

A reference controller implementation is in `firmware/station_controller/` (protocol core tested
on a PC against this contract; board layer uncompiled). Open questions for Salaar: whether he
adopts it or replaces it, the real motor driver range, and whether `device_t_us` shares a
timebase with the wearable stream.
